PREREQUISITES

The Eight Things Every Module Assumes You Know

Every module in this course links back to specific sections of these eight pages instead of re-explaining them. That's deliberate: if a module's tutorial keeps re-teaching "what a process is," you can never tell what that module actually adds. Learn these eight ideas once, here, and every module afterward is free to spend 100% of its words on the one new thing it proves.

These are not "browser" concepts. They're OS/systems concepts that happen to be the floor the entire browser security model stands on. If you already know some of these cold, skim them anyway once — the anchors (#section-name) are what later modules actually link to, so it's worth knowing where things live.

1Virtual Memory & Address Spaces

Why a "memory address" your program prints is a lie every single process gets told, on purpose. Feeds directly into Modules 1, 5, 11, 12, 13, 14.

→ Read: Virtual Memory & Address Spaces

2Privilege Rings (Kernel Mode vs. User Mode)

Why your code is never really "in charge" of the hardware, and who is. Feeds directly into Modules 2, 9, 10.

→ Read: Privilege Rings

3System Calls

The one legal door between user mode and kernel mode — and therefore the one place you can stand to watch, filter, or block anything a process tries to do to the outside world. Feeds directly into Modules 3, 9, 10, 15.

→ Read: System Calls

4Processes vs. Threads

The distinction that the entire multi-process browser security model (Site Isolation, sandboxing) is built on top of. Get this wrong and every later module misleads you. Feeds directly into Modules 4, 5, 8, 11.

→ Read: Processes vs. Threads

5Handles & File Descriptors

Why "everything is a handle" on Windows (and "everything is a file" on POSIX) — the abstraction that lets an OS revoke or restrict access to anything a process touches. Feeds directly into Modules 6, 7, 9, 10.

→ Read: Handles & File Descriptors

6Bytes, Hex, and Endianness

The literacy you need to read a memory dump or a packet capture without flinching. Feeds directly into Modules 1, 15, 16, 19.

→ Read: Bytes, Hex, and Endianness

7IPC Channels (the general idea)

Before pipes, sockets, or Mojo: the one abstract idea that two isolated things can only talk if they both deliberately open a channel. Feeds directly into Modules 6, 7, 8, and every "process talks to process" moment in Track 2.

→ Read: IPC Channels

8Origins & URLs

The exact, boring, precise definition of "origin" that the entire web security model (SOP, CORS, cookies, CSP) is a set of rules about. Feeds directly into Modules 17, 18, 29, 30, 31, 32, 33, 34.

→ Read: Origins & URLs

Don't try to memorize these in one sitting. Read one, then go start the module that cites it — the module is where the idea actually becomes useful, which is when it sticks.
