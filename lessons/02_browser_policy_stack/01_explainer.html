The Browser Policy Stack

Five real policies. One real page load runs through all five, in order, each catching a genuinely different class of risk.

00Why This Is Centralized

Modules 17, 18, 29, 30, and 31 each proved ONE policy mechanism correctly, in isolation — the right scope for learning each one without the others' details bleeding in and confusing the specific claim being tested. But "which of these five stops which kind of attack" is the single most common real confusion practitioners have about browser security, and untangling it requires seeing all five together, in the actual order a real page load exercises them.

02The Real Order, on One Page Load

  1. Before anything is sent: HSTS is checked (Module 31) — an http:// URL to a known HSTS host is rewritten to https:// before a single packet leaves the machine.
  2. The request goes out. If it's cross-site, SameSite (Module 29) decides which cookies ride along, based on the cookie's own attribute AND the request's context (top-level nav vs. subresource, safe vs. unsafe method).
  3. If the request is cross-origin and "non-simple," a CORS preflight (Module 18) happens FIRST, asking permission before the real request is sent at all.
  4. The response arrives. SOP (Module 17) decides whether the calling script is allowed to read its body — checking, among other things, whatever CORS headers (Module 18) the response carried.
  5. If the response is a page containing scripts, CSP (Module 30) gates which of them are even allowed to execute — checked before execution, independent of everything above it.

03The Pattern Worth Noticing

Every single one of these five policies is enforced by the BROWSER, on the CLIENT side — never the server deciding at request time, never a network-level restriction. The server's only role, across all five, is DECLARING a policy (a CORS header, a CSP header, an HSTS header, a cookie's SameSite attribute) — the browser is what actually checks it, every time, and it's checking a genuinely different thing at a genuinely different moment for each one. This is the single throughline worth internalizing: "is this safe" is never one check. It's five, at five different moments, each answering a narrower question than it sounds like it does.
