TRACK 2 · PHASE 9 · MODULE 30

csp_enforcement

Proves: CSP is a browser-side allowlist checked BEFORE a script would execute — not a content filter applied to output afterward — demonstrated by blocked scripts never reaching an "executed" list at all.

00Prerequisites

Module 29: cookies_samesite Module 19: html_tokenizer

01The Big Analogy

A secure office building's front desk has a printed, standing list of pre-approved delivery companies. A delivery driver doesn't get waved through and THEN checked while already inside handing over a package — the list is checked at the door, before entry, full stop. A driver not on the list is turned away before ever crossing the threshold, regardless of what's in the box or how convincing they seem. CSP is that standing list, checked at the browser's own front door, before a script is ever allowed to run — never a security guard chasing down script content after it's already loose inside.

02What Happens, Step by Step

  1. A page's server sends a Content-Security-Policy header — plain text, parsed the same way any other header is (Module 16).
  2. For each <script> the page tries to load — inline or with a src — the browser checks it against the script-src directive's allowed sources.
  3. 'self' matches the page's own origin; 'unsafe-inline' permits inline code; specific listed origins permit scripts from exactly those sources.
  4. Anything not matched is refused — before a single line of it would ever run.
