CORS (Cross-Origin Resource Sharing)

If SOP is "your mail is only opened by you, by default," CORS is a note the SENDER can attach that says "actually, I'm fine with this specific other person opening it too" — an explicit, sender-declared exception, never something the recipient decides for themselves.

CORS is a server-declared, browser-enforced RELAXATION of SOP's default. Module 18 proved its real two-part mechanism: for "non-simple" requests, a preflight OPTIONS round trip asks permission BEFORE the real request is even sent; and separately, the actual response must ALSO carry a matching Access-Control-Allow-Origin header, or the browser withholds it regardless of what the preflight said.

CORS doesn't replace SOP — it's a deliberate, narrow, opt-in EXCEPTION to it, for exactly the origins a server explicitly lists.

CORS is entirely about whether a script can READ a cross-origin response — it has nothing to do with whether COOKIES ride along on the request at all; that's SameSite's job. See the connections hub.
