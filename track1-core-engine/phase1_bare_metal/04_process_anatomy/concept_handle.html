Handle

A handle is the actual coat-check ticket in your OWN pocket — a private, unguessable-to-outsiders reference the attendant issued directly to you, that only means something because THEY, not you, keep the real record of what it's good for.

A handle is an opaque number, meaningful only inside the process that holds it, that the kernel maps (in a table only the kernel can see) to a real object and a specific set of GRANTED RIGHTS. Module 4's own demo drew this distinction directly: getting a process's PID is free and requires nothing; getting a HANDLE to that process required calling OpenProcess() with an explicit requested access mask, which the kernel could — and in a cross-privilege scenario, would — refuse.

Two processes can each hold a handle numbered 0x38 that refer to completely unrelated objects — the number alone means nothing outside the process holding it, unlike a PID, which is globally consistent.

A handle is obtained BY PRESENTING a token (your credentials) to the kernel, which checks it against the target object's own SID-based permissions before deciding whether to grant it. See the connections hub for the full chain.
