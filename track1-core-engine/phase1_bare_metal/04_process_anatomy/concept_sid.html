SID (Security Identifier)

If a token is your whole employee badge, a SID is ONE specific line printed on it — "Clearance Level: Medium," say. A badge carries several SIDs at once (your personal identity is one, each group you belong to is another) the same way a real badge might list a name AND a department AND a clearance tier, all as separate, individually-meaningful facts.

A SID is a structured identifier for ONE security principal — a specific user, a specific group, or (the form Module 4's own demo used directly) a specific integrity LEVEL. Module 4 read a real one: S-1-16-8192, decoded via win32security.ConvertSidToStringSid(), where the trailing 8192 is the actual Medium-integrity RID.

A token doesn't just have "one" SID — it carries a whole SET of them (your user SID, each group you're a member of, and your integrity-level SID among them), which is why comparing two tokens' "SIDs" always means specifying WHICH SID you're comparing.

SIDs are what a token is actually built FROM — and what the kernel checks a token's SIDs against when deciding whether to grant a handle. See the connections hub for the complete chain from a bare PID all the way to a granted handle.
